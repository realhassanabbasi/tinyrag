How it works

The whole pipeline — chunking, TF-IDF, retrieval, answering — is written by hand in pure Python. No sklearn, no numpy, no LLM.

01

Chunk

Documents split into a sliding window of 400 words with 80-word overlap.

→
02

Vectorize

TF-IDF from scratch, L2-normalized, English stopwords removed.

→
03

Retrieve

Cosine similarity ranks the chunks; the top-k go to the answerer.

→
04

Answer

Best sentence by IDF-weighted term overlap, quoted with its source.

What it can do

Six commands, one loop: index → ask → inspect → guard.

index

Build a persistent JSON index from a folder of .txt / .md files. Build once, ask anytime.

ask

Extractive answers with a citation — document, chunk, confidence. --sources N shows the ranked evidence behind it.

search

List the chunks that mention a word, with scores and excerpts — the same retriever ask uses, so they always agree.

stats

Documents, chunks, vocabulary, per-document counts, most common terms — read straight from the saved index.

refresh

Re-index only added or edited files; drop deleted ones. A no-change refresh says so.

check

Re-answer a saved question set after a refresh and flag answers that moved or vanished. CI-ready with --fail-on-change.

Honest limitations

  • English-only tokenizer — other languages won’t tokenize.
  • Keyword matching, not semantics — “car” won’t match “automobile”.
  • Small-scale by design — the whole index lives in memory as JSON; fine for notes and docs, not millions of pages.
